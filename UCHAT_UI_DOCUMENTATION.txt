uCHAT: COMPREHENSIVE UI, BACKEND & VERIFICATION DOCUMENTATION
================================================================================

1. ARCHITECTURAL & UI PHILOSOPHY
--------------------------------------------------------------------------------
uChat is built on a "Local-First & Edge-Compute" philosophy. The UI is designed 
to be a seamless, Progressive Web App (PWA) capable of wrapping into a mobile 
APK, requiring fluid touch interactions and strict "Dark Mode" compliance.

- Framework: React (TypeScript) + Vite
- Styling: Tailwind CSS
- Animation: motion/react (Framer Motion)
- Icons: lucide-react (Exclusively)
- Base Dark Palette: Zinc-based (`#121214`, `#1a1a1c`, `zinc-900`)

--------------------------------------------------------------------------------
2. PIXEL-BY-PIXEL UI MECHANICS & COMPONENTS
--------------------------------------------------------------------------------

A. Main Layout (App.tsx)
- The app operates on a split-pane layout for desktop (Sidebar + Main Chat) and 
  a single-view stacked layout for mobile.
- Mobile breakpoints (`sm:`) swap the left sidebar into a full-width drawer or 
  hide the main chat until a conversation is selected.
- Glassmorphism is heavily utilized: sticky headers use `bg-app-bg/80 backdrop-blur-xl`.

B. Chat Header (ChatHeader.tsx)
- Height: `h-[56px]` (Mobile), `h-[64px]` (Desktop).
- Avatar: `w-8 h-8` (Mobile), `w-10 h-10` (Desktop) with `object-cover`.
- Active Status: `w-2.5 h-2.5` green dot positioned absolute bottom-right of avatar 
  with a `border-2 border-app-bg` to carve out negative space.
- Icons: 
  - [Sparkles] Opens Aura AI
  - [Phone/Video] Triggers native WebRTC calls
  - [Palette] Toggles chat wallpaper
  - [Search] Opens inline search bar
  - [MoreHorizontal] Opens dropdown (Video, Search, Profile) on mobile.

C. Message Bubble (MessageBubble.tsx)
- Border Radius: Assymetrical. Own messages: `rounded-3xl rounded-br-sm`. 
  Contact messages: `rounded-3xl rounded-bl-sm`.
- Padding: `px-4 sm:px-5 py-2.5 sm:py-3.5`.
- Long Press/Tap Trigger: `onTouchStart` and `onMouseDown` invoke a 500ms `setTimeout`. 
  If not interrupted by `onTouchEnd`/`onMouseLeave`, the state `showContextMenu` 
  becomes true, revealing the context menu with a slight `window.navigator.vibrate(50)` 
  haptic feedback.
- Reactions: Positioned absolute `-bottom-3` on the left/right edge. Selected reactions 
  scale up slightly (`hover:scale-110`).

D. Chat Input (ChatInput.tsx)
- Input area dynamically scales its height based on content.
- Minimum Touch Targets: 44px (ensured via `p-2` or `p-3` on icon buttons).
- Background: `bg-app-surface` with a `border-app-border` top border.

3. BACKEND CONNECTION & DYNAMIC DATA IMPLEMENTATION
--------------------------------------------------------------------------------
To transition from the current mock UI state to a production backend, follow 
these architectural steps:

A. WebSocket Integration (Real-Time Engine)
- Setup a Socket.io or native WebSockets connection in a top-level `AuthProvider` 
  or a custom hook `useChatSocket`.
- Bind `socket.on('message', payload)` to append new messages to the `messages` array 
  in `App.tsx`.
- Optimistic UI: When a user sends a message, immediately push it to the local array 
  with `status: 'sent'`. Emit the event to the server. When the server acknowledges, 
  update the status to `delivered`.

B. Database Sync (Local + Cloud)
- Use `IndexedDB` (via Dexie.js or localForage) to store messages locally (Edge-compute).
- On initial load, fetch recent messages from the local SQLite/IndexedDB.
- Run a background sync via standard REST/GraphQL endpoints to fetch missing messages 
  and resolve conflicts.

C. Connecting the Reaction Engine
- When a user clicks a reaction in `MessageBubble.tsx` (the `toggleReaction` function), 
  dispatch a POST/Socket request: 
  `emit('reaction_update', { messageId, emoji, userId, action: 'add|remove' })`.
- Listen for incoming `reaction_update` events globally to re-render the bubble 
  instantly for other users.

4. VERIFICATION & TESTING PROTOCOLS
--------------------------------------------------------------------------------
To ensure the app maintains its pixel-perfect fidelity and robust functionality, 
run the following rigid test matrices.

A. Functional Verification Protocol
1. [Message Send Flow]
   - Step: Type text -> Press Send.
   - Verify: Input clears immediately.
   - Verify: Bubble appears with 'sent' tick.
   - Verify: Socket payload matches UI schema.
2. [Reaction Flow]
   - Step: Long press bubble (500ms).
   - Verify: Haptic vibration triggers. Context menu appears.
   - Step: Tap '❤️' reaction.
   - Verify: Context menu closes. Pill appears at `-bottom-3`.
   - Verify: Backend `POST /api/reactions` succeeds.
3. [Aura AI Trigger]
   - Step: Tap Sparkles icon.
   - Verify: Modal triggers `AnimatePresence` with `scale: 0.95` to `scale: 1`.

B. Rigid Pixel-Perfect UI Verification
1. [Touch Target Validation]
   - Step: Inspect all interactive elements (`button`, `a`).
   - Verify: Computed height and width are strictly >= 44px (including padding).
2. [Contrast Ratio Check]
   - Step: Run Lighthouse / WCAG Accessibility tools.
   - Verify: Zinc dark mode text (`#ffffff` at 90% opacity against `#121214`) 
     yields a contrast ratio > 4.5:1.
3. [Animation Dropped Frames]
   - Step: Open Chrome DevTools -> Rendering -> FPS meter.
   - Verify: Opening the reaction context menu or sidebar drawer does not drop 
     frames below 60FPS. Ensure `motion.div` uses `transform` and `opacity` 
     exclusively (no width/height animation without layout transitions).
4. [Responsive Breakpoints]
   - Step: Resize window across 320px, 768px, and 1024px.
   - Verify: Header padding shifts precisely from `px-3` to `px-5`. 
   - Verify: Chat grid never triggers horizontal scrollbars.
